# EDGEdeck: notes for Claude sessions

EDGEdeck is a mod manager for Cyberpunk 2077 built as a VS Code extension. It is one of four repos by the same owner: REDnode (runtime scripting), REDcode (the IDE), REDbridge (the engine host, GPL-3.0) and EDGEdeck (this one). REDnode's `CLAUDE.md` and `docs/dev-setup.md` set the shared conventions. The name: a deck of mods, a nod to the cyberdeck, and the mods waiting "on deck" before you deploy them.

## The design goal

Simplicity with a friendly and obvious UI. Rules that follow from it:

- One list of mods. Four verbs: add, turn on or off, deploy, remove. Everything else goes in the detail panel.
- Plain words: On/Off, Deploy and Undo deploy, Library, Kind, Conflicts and Wins. Never "activate", "purge", "staging", "mod type", "profile".
- Decide, don't ask. A dialog appears only when a wrong guess would lose data.
- Safe by default: never delete a file EDGEdeck did not put there; everything deployed is in the manifest and can be undone.
- Works offline and alone. REDcode and REDbridge add features when present and are found at runtime with `extensions.getExtension(...)`. Never import their code.

## Releases

- **Publishing (first release on both stores: 0.26.0, 2026-10-14):** push a tag `vX.Y.Z` that matches `package.json`; `.github/workflows/publish.yml` checks the match, runs typecheck, build and smoke, packages `--target win32-x64`, publishes to the VS Code Marketplace (`VSCE_PAT`) and Open VSX (`OVSX_PAT`, skipped while unset) and makes the GitHub release with the CHANGELOG section as notes. Do not also run `gh release create` by hand. Both tokens are Edgemodders organisation secrets; `verify-tokens.yml` (run by hand) checks them. Publisher id `edgemodders` on both. `"preview": true` until the owner says otherwise.
- **Nexus Mods:** the page's source is `nexus/description.bbcode` (form fields and steps in `nexus/README.md`; `node scripts/check-bbcode.mjs nexus/description.bbcode` before pasting). The publish workflow also builds `dist/EDGEdeck-<version>-nexus.zip` (`scripts/nexus-zip.mjs`: the vsix, README.txt with install steps, licenses) and attaches it to the GitHub release; the owner uploads it to Nexus by hand with Mod Manager Download off.
- **npm (0.26.4):** `@edgemodders/edgedeck-mcp` is published by the same workflow at EDGEdeck's version (`NPM_TOKEN`, an Edgemodders organisation secret, provenance on). `scripts/npm-package.mjs` copies `dist/mcp.js`, `dist/core.js`, `bin/edgedeck.mjs`, `bin/edgedeck-mcp.mjs`, `bin/7za.exe`, notices, LICENSE and `docs/npm.md` (its README) into `dist/npm`; bins `edgedeck-mcp` and `edgedeck`, `os: win32`. Keep `docs/npm.md`'s tool table in step with `src/mcp.ts`.
- `ThirdPartyNotices.txt` is written by `esbuild.mjs` on every build from what extension.js and mcp.js bundle, plus 7-Zip for `bin/7za.exe`. Commit it when it changes.

## Conventions

- Commit straight to `main` and push, in small logical commits. Agree the plan in chat first. PRs only for large or risky changes.
- Git identity is set per repo to `CyberbuildsAI` with the GitHub no-reply email. Never change the global identity.
- Two machines push to this repo: `git fetch` and `git rebase origin/main` before every push, after committing.
- Record every tool install in `docs/dev-setup.md`, with versions and exact commands.
- Writing style: plain, short sentences, tables for comparisons. Mark anything unverified as unverified.
- House style is the HUD look. `tools/brand/render.ps1` regenerates the banner, badges and icon; re-run it when versions in the badges change.
- Never commit game files, mod archives or anything extracted from the game.
