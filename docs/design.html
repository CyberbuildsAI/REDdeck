REDdeck

A mod manager for Cyberpunk 2077 that lives inside REDcode and VS Code. One list of mods, four verbs, no jargon. It keeps a library of mods outside the game folder, deploys the ones you turn on, and shows you the conflicts Vortex cannot see because it can read inside the archives.

Goal: simple, friendly, obvious Own repository, loaded by REDcode when present One game, one list, hardlink deploy Name: REDdeck, a deck of mods

01Goal and the rules that follow from it

The project goal

Simplicity with a friendly and obvious UI. Vortex works, but it is built for two hundred games and it shows: profiles, activators, purge, phases, rules, dialogs that ask the user to decide things the tool could decide. REDdeck supports one game and can be as plain as that allows.

Rules
  • One list. Every mod in one list, grouped by what it is. No separate pages for downloads, plugins and load order.
  • Four verbs. Add, turn on or off, deploy, remove. Everything else lives in a mod's detail panel and is optional.
  • Plain words. "Deploy" not "activate". "Turn off" not "disable in profile". "Conflicts" not "file override rules". The word list is in section 04.
  • Decide, don't ask. Where a file goes, whether to hardlink or copy, what wins a conflict by default: the tool decides and shows what it decided. A dialog appears only when a wrong guess would lose data.
  • Safe by default. REDdeck never deletes a file it did not put there, keeps a manifest of what it did, and can undo all of it with one command.
  • Works offline, works alone. No Nexus account needed to add a mod from a file. No REDcode or REDbridge needed to run; they add features when present.
Scope
  • In: install from a file or a Nexus link, enable and disable, deploy and undo, the core frameworks, archive load order, REDmod deploy, conflicts, updates from Nexus, import from Vortex.
  • In, through REDcode: install a packed project with one click and test it in the game. REDnode mods as a mod kind.
  • Out for v1: collections, multiple games, FOMOD installers, Nexus login by OAuth (a personal API key is enough), mod merging, save editing, launching the game through a launcher wrapper.

02How Cyberpunk mods are installed

Read on 2026-10-11 from a reference machine whose game folder Vortex manages (361 deployed files from 16 mods). A Cyberpunk mod is a set of files dropped into known places under the game folder. There is no plugin list like Bethesda games have; the folder is the registry.

The frameworks are mods too

RED4ext, CET, redscript, ArchiveXL, TweakXL, Codeware, Audioware, input_loader and mod_settings are all installed from Nexus like any mod, and most other mods depend on one or more of them. REDdeck treats them as mods in a pinned "Frameworks" group at the top of the list, and checks their versions against the game version, because a game patch is the usual reason a modded game stops starting.

The name

REDdeck: a deck of mods, a nod to the cyberdeck every player knows, and the mods waiting "on deck" in the library before they are deployed. Chosen 2026-10-11 after REDmods (one letter from CDPR's REDmod) and REDpack ("pack" is the verb WolvenKit and REDcode use for building an archive). CDPR's official modding system is called REDmod. It owns the mods/ folder, redMod.exe and the -modded launch flag, and the Vortex extension talks about "REDmod deploy" and "REDmod load order". REDdeck will still say "REDmod" in its UI when it prepares those packages; the two words are far enough apart to read.

03What Vortex solves, and what to keep

Vortex is an Electron app (React, Redux, TypeScript, GPL-3.0) with one extension per game. The Cyberpunk extension (version 0.12.1, by KellieAtTheLab) is 64 source files and defines 34 installer types, one per mod layout it knows how to recognise and fix up. Vortex itself keeps mods in a staging folder under AppData, hardlinks them into the game folder, and records what it did in vortex.deployment.json. The user is right that some of its complexity is unavoidable: the problems below exist whether or not the UI shows them.

Must solve too
  • A library outside the game folder. Otherwise "turn off" means "delete" and "update" means "hope".
  • Deployment and undo. Hardlinks when the library is on the game's drive (Vortex checks with a canary file), copies otherwise. A manifest of every deployed file. Undo removes only files in the manifest.
  • Changes made outside the manager. The game, the launcher, Steam's verify, CET's own updater and the user all touch the folder. Vortex classifies four change types and offers six actions. REDdeck reduces this to two questions, section 05.
  • Recognising a mod's layout. Mod archives from Nexus are inconsistent: some are rooted at the game folder, some at archive/pc/mod, some are a bare .archive, some ship a readme and a choice of options. Vortex has 34 installers for this. REDdeck has one classifier and one "where should this go?" picker, section 06.
  • Load order for archives and REDmod. Vortex writes modlist.txt and runs redMod.exe deploy with a mod list.
  • Nexus links. The "Mod manager download" button on Nexus opens an nxm:// link. Someone must handle it.
  • Conflicts. Two mods shipping the same file path. Vortex shows them and lets the user set before/after rules per pair.
Can drop
  • Multi-game. Game discovery, per-game extensions, generic "mod types" with their own deployment targets.
  • Profiles as a first-class concept. Most people have one. REDdeck has loadouts instead (0.26): one is always active and saves itself, the others are files the page can edit, and the order is shared. No profile switching ritual, no per-profile load order.
  • 34 installers. Most exist to be strict about layouts. A picker that shows the user the folder tree and a guess is friendlier and covers the long tail.
  • Collections. A Nexus product with its own GraphQL API and a Vortex-specific manifest. Out of scope.
  • Redux state, LevelDB, the extension API. REDdeck state is one JSON file per mod and one for the library, which is also what makes it AI-readable.
  • Symlink and move deployment, elevation. Hardlink or copy covers Windows and both drive layouts.
  • Jargon. Activator, purge, phase, rule, staging, mod type, primary tool.

04The UI

One view in the REDcode activity bar, or its own activity bar icon when REDcode is not installed. The main part is a list. Selecting a mod opens its detail panel in the editor area, a webview in the HUD style. The status bar shows one thing: whether what is deployed matches the list.

What each part does

  • Checkbox turns a mod on or off. Nothing happens on disk until Deploy. The Deploy button shows how many changes are waiting, so the state is never a mystery.
  • Add mod accepts a .zip, .7z or .rar, a folder, a bare .archive, or a Nexus link pasted in. Drag and drop onto the view does the same.
  • Nexus opens the mod's Nexus page, checks for updates, and is where the API key lives. Without a key, the button still opens pages in the browser.
  • Status is one short phrase in plain words: deployed, off, not deployed yet, update available, 1 conflict, needs RED4ext, file changed in game folder.
  • Kind chips say what is inside, so a user learns the ecosystem by looking at the list.
  • Detail panel (on select): description and Nexus page, version and update, the files it deploys and where, conflicts with the winner marked, load order position with up and down buttons, its REDmod info if any, Remove.

Standalone, and loaded by REDcode

The extension lives in its own repository, REDdeck, under MIT, and is packaged and published on its own. It activates on its own events (its view, its commands, an nxm URI). REDcode's extension pack lists it, so installing REDcode installs it. When REDcode (edgemodders.redcode, until 0.6.0 redcode-core) is present, it does two things: it contributes "Install into REDdeck" to the project's packed output, and it hands its bridge client to reddeck through the exported API, which turns on archive-level conflict detection. When it is absent, REDdeck still manages the game; conflicts are then detected by file path only, and the detail panel says so.

The library

// %USERPROFILE%\REDdeck (default; user can move it, ideally onto the game's drive)
library.json                      // game path, game version, order, settings
library/
  trauma-team-subscription/       // one folder per mod, files laid out exactly as they deploy
    mod.json                      // name, version, kind(s), nexus {modId, fileId, md5}, enabled, added, files[]
    archive/pc/mod/TraumaTeamSubscription.archive
    archive/pc/mod/TraumaTeamSubscription.archive.xl
    r6/scripts/TraumaTeamSubscription/...
  testmod/                        // installed from a REDcode project: mod.json says source: project, path
downloads/                        // original archives kept for reinstall; md5 named
deployed.json                     // mirror of <game>\reddeck.deployment.json

Because each mod folder is laid out exactly as it deploys, "what will this do to my game folder" is answered by listing the folder, and a person or an assistant can inspect or fix a mod with a file explorer. The classifier's job is only to produce that layout once, at add time.

Deployment

  • Deploy computes the difference between the manifest and the enabled mods, creates hardlinks (same drive) or copies (otherwise, chosen once at setup with a one-line explanation), writes modlist.txt from the archive order, runs redMod.exe deploy if any enabled mod is a REDmod package, and writes the manifest. Progress in the status bar, details in the Output channel.
  • Undo deploy removes every file in the manifest and nothing else, then removes folders it emptied.
  • Changes outside REDdeck. On Deploy and on view refresh, each manifest entry is checked. Hardlinks are checked by file identity like Vortex does; copies by size and mtime. Two cases reach the user: a file changed in the game folder (keep it, which imports it into the library, or put the mod's file back, the default) and a file missing from the game folder (put back silently, which is what the user meant by enabling the mod). Vortex's other two cases, the library file changed or removed, are the user's own edits in the library and simply redeploy.
  • Conflicts between mods are resolved by order in the list: higher wins. Deploy links the winner. The detail panel shows what lost and why.
  • Game version is read from the executable's version resource at every refresh. If it changed since the last deploy, the frameworks group shows which ones have a newer file on Nexus for it.

06Mod kinds and the classifier

Instead of 34 installers, one classifier with a short rule list. It walks the extracted archive, finds the deepest folder that contains a known top-level name, and maps every file to a target under the game folder. Files it cannot place are shown to the user in a tree with a guess, not rejected.

A mod can be several kinds at once; Drive an Aerial Vehicle on the reference machine is archive, reds, cet, tweak and audioware together. Kinds are chips, not categories, and a mod is never split into several entries.

07Conflicts, the part Vortex cannot do

File conflicts (always)

Two enabled mods deploy the same relative path. Detected from the library alone. The list shows "1 conflict" on both, the detail panel shows the files and the winner, and up or down in the list changes the winner.

Archive conflicts (with REDbridge)

Two .archive files with different names that both contain base\characters\...\t0_000_pma_base__full.mesh conflict inside the game, and no file-level manager sees it. With REDbridge, REDdeck opens every enabled mod archive, lists its resource hashes, and intersects. It shows the overlapping resources, which archive wins under the current order, and whether the mods' .archive.xl files change that. This is the same check WolvenKit's conflicts CLI command does, surfaced where the user decides the order. It needs one new bridge method: archive.openMod(path), returning the file list of an archive outside the game folder.

Conflicts are information, not errors. Most are intentional (a texture replacer over a body mod). The UI marks them, explains the winner in one sentence, and offers reorder. It never blocks Deploy.

08Nexus Mods

What the API gives
  • REST v1 at api.nexusmods.com/v1 with a personal API key from the user's Nexus account page, sent as a header. Rate limited to 2,500 requests a day, then 100 an hour. REDdeck caches mod and file metadata and checks updates once a day or on demand.
  • Mod and file metadata: games/cyberpunk2077/mods/{id}.json, /files.json. Identify a file the user already has by hash: mods/md5_search/{md5}.json. Updates: compare the newest file for the user's installed file's category.
  • Download links: files/{fileId}/download_link.json works directly for Premium members. Free members get links only with the key and expires parameters that the website puts into an nxm:// link when they press "Mod manager download". So the nxm handler is what makes downloads work for everyone.
  • Nexus asks tools to identify themselves with an application name and version in the user agent, and to register the application. Both go on the checklist before release.
The nxm link

Format: nxm://cyberpunk2077/mods/{modId}/files/{fileId}?key=...&expires=...&user_id=.... VS Code cannot register a custom protocol for an extension, but it does handle vscode://publisher.extension/... links. REDdeck installs a tiny forwarder (reddeck-nxm.cmd) under HKCU\Software\Classes\nxm that opens vscode://cyberbuilds.reddeck/nxm?url=..., and the extension's URI handler downloads and adds the mod. Registration is a button in settings, "Handle Nexus download links", which also says if Vortex currently has them, and a matching button to give them back. Pasting a link into Add mod always works regardless.

09Living next to Vortex

  • Detect. If vortex.deployment.json is in the game folder, REDdeck opens read-only: it lists what Vortex deployed, explains that two managers cannot deploy into one folder, and offers "Import from Vortex". The user runs Vortex's purge, then REDdeck deploys.
  • Import. Vortex's staging folder (%APPDATA%\Vortex\cyberpunk2077\mods) holds one folder per mod already in deployable layout, with the Nexus mod id, version and timestamp in the folder name for mods that came from Nexus. Import copies them into the library, keeps the Nexus ids, and marks them on or off by reading which ones appear in the deployment manifest. Collection folders (collection.json only) are skipped.
  • Never both. REDdeck refuses to deploy while Vortex's manifest is present, and writes its own manifest under a different name so Vortex refuses in turn.

10The REDcode and REDnode loop, and AI

From project to game in one click

REDcode's pack step produces packed/archive/pc/mod/<Mod>.archive. With REDdeck present, the project gets an "Install into REDdeck" command and a "Test in game" command that installs, deploys only that mod's changes and launches the game. The library entry remembers its source project, so a rebuild shows "rebuilt, not deployed" in the list and Deploy picks it up. The same path serves REDnode mods: a REDnode package is a kind, and the REDnode runtime plugin is a framework.

AI-first

All state is JSON files in the library, so an assistant can read what is installed, enabled and conflicting without the UI. The exported commands (reddeck.add, reddeck.setEnabled, reddeck.deploy, reddeck.list) are callable by other extensions and by Claude through VS Code. Later, the same core ships as a reddeck npm CLI and as MCP tools next to REDbridge's, so "install these three mods and tell me if anything conflicts" is one request.

12Roadmap

Status 2026-10-13, version 0.16.0

M0 to M3 are built and in daily use on two PCs, M4's REDdeck side and M5's loadouts and command line too. Beyond this draft: one row per mod with a version dropdown, a pending-changes list, a wide table page with search and facets, Get REDbridge with a daily update check, game detection through Steam's library list, sizes everywhere, and a Set up group for a new install. Left: MCP tools, REDnode packages as a kind, the REDcode-side hand-off. Not on the Marketplace. The guide covers use and the docs index keeps the phase status.

M0DECIDE

Name, library location, word list

Name settled: REDdeck, with its own repository (renamed from REDpack). Default library folder. Agree the plain-words table and the four verbs. Scaffold the repository in the house style with the view and an empty library.

M1LIBRARY

Add, on and off, deploy, undo

Add from zip, 7z, rar and folder with the classifier and picker. The library layout and mod.json. Hardlink and copy deployment with the manifest, undo, change detection, modlist.txt. Status bar and Output channel. Vortex detection and import. REDdeck manages the reference machine's game end to end.

M2KINDS

Frameworks, REDmod, conflicts

Frameworks group with game version check. REDmod packages and redMod.exe deploy with order. File conflicts with winner and reorder. Archive conflicts through REDbridge (archive.openMod). Detail panel webview.

M3NEXUS

Links, metadata, updates

API key setting, mod pages and metadata, md5 identification of existing files, update check, nxm forwarder and URI handler, downloads for Premium and free members. Application registration with Nexus.

M4LOOP

REDcode and REDnode

"Install into REDdeck" and "Test in game" from a REDcode project. REDnode packages as a kind. Rebuild detection. Exported API used by REDcode.

M5SHARE

Loadouts, CLI, MCP

Save and load a list as a loadout file. reddeck CLI on npm over the same core. MCP tools beside REDbridge's. Publish to Open VSX and the Marketplace.

13Open questions

  • Library location. User profile by default, or next to the game by default so hardlinks always work?
  • Should REDdeck manage the frameworks (install RED4ext, CET and redscript itself) or only recognise them? Managing them is friendlier and is what Vortex does.
  • Launching the game. A "Play" button that launches with -modded when REDmod packages are on is obvious and friendly. Steam launches it through REDlauncher, which complicates this. Worth a small investigation.
  • Which mods do you run on the big PC? A real list drives the classifier's test cases.
  • Collections stay out, or is importing a collection's mod list (without Vortex) worth it later?
